=== FILE - Files ===

The ANS file words are BUILT IN here - there is no module to load. They sit
on the kernel's FS_* calls (X816_core doc/KERNEL.md 5.2) through the
primitives in asm/file.asm; there is no CBDOS, no device 8 and no logical
file numbers, because there is no IEC bus.

fileid is a KERNEL HANDLE, 1..5, and FIVE IS THE WHOLE POOL - shared with
the interpreter, which holds one handle per NESTED SOURCE. Booting is
already four deep (base.fs is open while it includes AUTORUN, which
includes a suite, which includes a test), so a program that opens files
from inside nested includes can run out. Running out reports ior 3, which
reads as "no space" but means "no handle": close what you opened.

ior is the kernel's own error number, NOT a Forth THROW code: 0 success,
1 no such call, 2 not found, 3 no space/handle, 4 bad argument, 5 I/O
error, 6 exists, 7 not empty. These words RETURN it; they do not throw.

[x] INCLUDE ( "name" -- ) - load and interpret a file by name. INCLUDE GAME.FTH
[x] INCLUDED ( addr len -- ) - load and interpret the file named by a string. S"
    GAME.FTH" INCLUDED
[ ] INCLUDE-FILE ( fileid -- ) - interpret the rest of an already-open
    file. The X16 staged it through the 8 KB bank window and could not
    nest; here it would be an ordinary buffer in flat memory.
[x] REQUIRE ( "name" -- ) - include a file only once, by name.
[x] REQUIRED ( addr len -- ) - include a file only once, by string.
[x] OPEN-FILE ( addr len fam -- fileid ior ) - open an EXISTING file. Only
    R/O is accepted; W/O and R/W return ior 1 and open nothing. That is not
    an oversight: this kernel's only write mode CREATES, truncating whatever
    was there, so honouring W/O here would silently empty the caller's file.
    Ask for that by name with CREATE-FILE.
[x] CREATE-FILE ( addr len fam -- fileid ior ) - create a file, TRUNCATING it
    if it already exists. fam is accepted and ignored: there is one kind of
    created file, and it is open for writing.
[x] CLOSE-FILE ( fileid -- ior ) - close a file. This is also the SYNC point:
    the size in the directory entry is written back here.
[x] DELETE-FILE ( addr len -- ior ) - delete a file.
[x] RENAME-FILE ( a1 u1 a2 u2 -- ior ) - rename a1/u1 to a2/u2.
[x] READ-FILE ( addr u fileid -- u2 ior ) - read up to u bytes. A SHORT read
    is not an error: u2 below u, and 0 with ior 0, is how end of file
    arrives. addr is a full 24-bit address, so reading straight into far
    (SDRAM) space works with no bounce buffer.
[x] WRITE-FILE ( addr u fileid -- ior ) - write u bytes at the current
    position. Writes append while the file stays open.
[x] READ-LINE ( addr u fileid -- u2 flag ior ) - read a line, stopping at LF
    and discarding a CR before it. flag is false ONLY at end of file: a last
    line with no terminator still reads as a line, and the call after it
    reports the end. One kernel crossing per byte - buy speed with your own
    buffer and READ-FILE if it matters.
[x] WRITE-LINE ( addr u fileid -- ior ) - write u bytes followed by LF.
[x] FILE-POSITION ( fileid -- ud ior ) / REPOSITION-FILE ( ud fileid -- ior ) -
    get/set the position. Seeking backwards is supported and costs a re-walk
    of the cluster chain, which fat32.c only follows forwards.
[x] FILE-SIZE ( fileid -- ud ior ) - size in bytes.
[x] FILE-STATUS ( addr len -- x ior ) - does it exist? x is 0; ior 0 means
    yes. Implemented by opening read-only and closing again, so it costs a
    handle for the duration and nothing afterwards.
[x] R/O ( -- fam ) read-only. W/O write-only and R/W read/write are DEFINED
    and REFUSED by OPEN-FILE, as above; W/O is what CREATE-FILE does anyway.
    There is no BIN: every file here is bytes, and no mode changes that.
[x] COMPARE ( a1 u1 a2 u2 -- n ) - listed here too because checking a file
    read back is what it is for. -1, 0 or 1. (Also in STRING.)
[ ] INCLUDE-FILE ( fileid -- ) - interpret an already-open file. NOT
    implemented: the interpreter's source stack (asm/io.asm) is entered by
    INCLUDED, which opens the file itself, and handing it a handle somebody
    else opened means opening those internals up. INCLUDED does the job.
[x] RESIZE-FILE ( ud fileid -- ior ) - PRESENT AND REFUSES: no kernel call
    exists, so it returns ior 1 rather than 0. Ticked because it is a real
    word with a defined answer, not a missing one - a caller gets a refusal
    it can test, not an undefined-word error.
[x] FLUSH-FILE ( fileid -- ior ) - the same, for the same reason.
    CLOSE-FILE is the sync point on this machine.

--- directories (kernel DIR_* / FS_CHDIR / FS_MKDIR) ---
Paths are ASCII with / separators, absolute or relative to the working
directory, and "." and ".." both work. There is no device number and no
DOS command channel: the X16 words below sent command strings to a CBM
drive over the IEC bus, and this machine has no IEC bus.

[x] DIR ( -- ) - list the working directory: name, then size, or <DIR>
    where a size would be. FAT32 stores 0 as a directory's size, and a
    bare 0 in a size column tells you nothing.
[x] CD ( c-addr u -- ior ) - change directory. S" .." CD goes up, S" /"
    CD goes to the root. This moves the KERNEL's working directory, the
    same one the prompt uses, so a program and its user cannot disagree
    about what "../X" means.
[x] PWD ( -- ) - print the working directory.
[x] CWD ( -- c-addr u ior ) - the working directory as a string, in a
    resident 80-byte buffer (KFS_PATH). Copy it if you need it to
    survive the next call.
[x] MKDIR ( c-addr u -- ior ) - create a directory.
[x] RMDIR ( c-addr u -- ior ) - remove an EMPTY one. A non-empty
    directory is refused rather than orphaned, which is the only thing
    between a mistyped name and lost files.

Walking a directory yourself, when DIR's format is not what you want:
[x] DIR-OPEN ( c-addr u -- handle ior ) - open a directory for reading.
    Handles are 129 up, from a pool of TWO, and separate from file
    handles - so one listing must be closed before another starts.
[x] DIR-NEXT ( handle -- flag ior ) - read one entry into DIRENT. flag
    false means the end, with ior still 0: running out is not an error.
[x] DIR-CLOSE ( handle -- ior ) - give the handle back.
[x] DIRENT ( -- addr ) - the 18-byte entry buffer the above fills:
    name at +0 (13 bytes, NUL terminated), attributes at +13 (bit 0 set
    = directory), size at +14 (32 bits, 0 for a directory).
[x] DIRENT-NAME ( -- c-addr u ) / DIRENT-DIR? ( -- flag ) /
    DIRENT-SIZE ( -- u ) - read those three fields.
    : LIST S" ." DIR-OPEN DROP
      BEGIN DUP DIR-NEXT DROP WHILE DIRENT-NAME TYPE CR REPEAT
      DIR-CLOSE DROP ;

--- durexForth: disk / DOS command channel (X16, not ported) ---
Every word here is a CBM DOS concept - a device number, a command
channel, an error channel - and none of them exists on this machine.
The replacements are above: LS is DIR, DOS/SEND-CMD/RDERR have no
counterpart because there is no drive to talk to, and OPEN/CLOSE are
OPEN-FILE/CLOSE-FILE.
[ ] DEVICE ( n -- ) - set the current disk device number (default 8).
[ ] DOS ( "cmd<cr>" -- ) - send the rest of the line to the drive command channel, print the reply.
[ ] SEND-CMD ( addr len -- ) - send a command string to the drive and print its response.
[ ] RDERR ( -- ) - read and print the drive's error channel.
[x] LS ( "pattern" -- ) - list the directory. The pattern is a plain
    SUBSTRING, not a glob: names come back 8.3 from the kernel and matching
    "*.TXT" would be pretending to a shell this machine has not got.
[ ] RDIR ( addr -- ) - print a directory previously loaded at addr.

[x] OPEN ( c-addr u fam -- fileid ior ) - open a file (like OPEN-FILE).
[x] CLOSE ( fileid -- ior ) - close a file.
