=== MEMORY - Memory ===

X816: cells are 32-bit (4 bytes) and hold flat 24-bit byte addresses, so
every word below reaches all 16 MB - there is no banking and no window.

[x] @ ( addr -- x ) - fetch a cell. X @
[x] ! ( x addr -- ) - store a cell. 42 X !
[x] C@ ( addr -- c ) - fetch a byte.
[x] C! ( c addr -- ) - store a byte.
[x] W@ ( addr -- u ) - fetch 16 bits, zero-extended into the cell.
[x] SW@ ( addr -- n ) - the same, sign-extended: for a field that was
    signed when it was written.
[x] W! ( x addr -- ) - store the low 16 bits of x.
[x] W, ( x -- ) - compile 16 bits into the dictionary at HERE.

THE 16-BIT WORDS ARE NOT AN AFTERTHOUGHT. A cell is 32 bits here, so a
two-byte field read with @ takes FOUR bytes and calls the next field's
low half part of this one - and the field after it is then read from the
wrong place, which is how the bug hides. Every 16-bit structure this
port has met wanted these: BMX's image header, a sprite's attributes, a
tilemap cell, the compiler's own branch operands (W! and W, are what it
patches them with). If you are reading a file format or a hardware
record, count the bytes in the SPEC and use the word that matches:

    hdr 6 + w@     \ the width, two bytes, as the format defines it
    hdr 6 + @      \ four bytes: the width AND the height, as one number

Stale code from before the 32-bit cells is the same mistake wearing a
different hat: `2*` next to `+ @` was correct when a cell was two bytes
and is an off-by-half now.
[x] 2@ ( addr -- x1 x2 ) - fetch a double / two cells.
[x] 2! ( x1 x2 addr -- ) - store two cells.
[x] +! ( n addr -- ) - add n to the cell at addr. 1 X +!
[x] , ( x -- ) - compile a cell into the dictionary at HERE. CREATE T 1 , 2 , 3 ,
[x] C, ( c -- ) - compile a byte into the dictionary.
[x] HERE ( -- addr ) - next free dictionary address.
[x] ALLOT ( n -- ) - reserve n bytes of dictionary space. CREATE BUF 100 ALLOT
[x] UNUSED ( -- u ) - bytes of dictionary space remaining. UNUSED .
[x] PAD ( -- addr ) - address of a scratch buffer (not preserved across words).
[x] ERASE ( addr u -- ) - set u bytes to 0.
[x] FILL ( addr u c -- ) - set u bytes to character c.
[x] BLANK ( addr u -- ) - set u bytes to spaces.
[x] MOVE ( src dst u -- ) - copy u bytes, handling overlap correctly.
[x] CMOVE ( src dst u -- ) - copy u bytes low -> high.
[x] CMOVE> ( src dst u -- ) - copy u bytes high -> low.
[x] CELL+ ( addr -- addr+4 ) - advance one cell.
[x] CELLS ( n -- n*4 ) - n cells in bytes. 3 CELLS  ->  12
[x] CHAR+ ( addr -- addr+1 ) - advance one char.
[x] CHARS ( n -- n ) - n chars in bytes (1 byte/char here).
[x] ALIGN ( -- ) - align HERE (no-op on this byte-addressed CPU).
[x] ALIGNED ( addr -- addr ) - align an address (no-op here).

--- durexForth ---
[x] DUMP ( addr -- ) - hex + ASCII dump of 8 lines starting at addr.
[x] N ( -- ) - dump the next block (continues the previous DUMP).

--- X816 far data space ---
The dictionary lives in the four single-cycle BRAM banks $01-$04, where an
instruction fetch costs one cycle. Bulk DATA belongs behind it, in SDRAM:
a second bump pointer, FAR-HERE, hands out $05:0000-$DF:FFFF. A far block
is an ordinary address - @ ! C@ C! MOVE FILL ERASE all reach it.

[x] SDRAM ( -- addr ) - first address of the far data space, $50000.
[x] SDRAM-SIZE ( -- u ) - its size in bytes, 14352384.
[x] FAR-HERE ( -- addr ) - next free far address. A VALUE: save and restore
    it with TO to release a block by hand.
[x] FAR-UNUSED ( -- u ) - far bytes remaining. FAR-HERE + FAR-UNUSED is
    always the top of the space.
[x] FAR-ALLOT ( u -- ) - claim u far bytes, THROWing -8 if the space cannot
    cover it. FAR-HERE 1000 FAR-ALLOT
[x] FAR-BUFFER: ( u "name" -- ) - claim u far bytes and name their address.
    $10000 FAR-BUFFER: SCREENBUF
[x] FAR-EMPTY ( -- ) - release the whole far space; every address handed out
    before it becomes garbage. MARKER also restores FAR-HERE.
