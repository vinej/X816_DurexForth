=== ADVANCED - game math, clipped graphics, sound FX ===

Ported from C:\quartus\projects\x16_library (see that tree for the
assembly originals and their names).

System / IRQ (base.fs - no module needed)
[x] IRQ ( xt -- ) - run xt on every vertical blank; 0 disarms. A handler
    must not THROW and must not enable interrupts, and must put back
    VERA's CTRL and address ports if it touches them: it runs inside
    whatever word was executing when the interrupt landed.
[x] LINE-IRQ ( xt line -- ) - run xt each frame at a raster line.
[x] SPRCOL-IRQ ( xt -- ) / COLLISIONS - sprite-collision interrupt.
[ ] AFLOW-IRQ ( xt -- ) - arms the slot, but the audio-FIFO enable bit
    does not stick on this hardware (writing 8 to $9F26 reads back as no
    enables), so it will not fire. The kernel excludes AFLOW from its
    acknowledge for the same reason.
    Register save/restore words are not needed: the core IRQ dispatcher
    saves W/W2/W3, the RAM bank, VERA CTRL and both data-port addresses
    around every armed word.

Game math (NEEDS ADVANCED) - all of this is in, and tested by testadv.
[x] RND-SEED RND16 RND8 - 16-bit xorshift PRNG (zero seed nudged off).
[x] SIN8 COS8 SIN8U COS8U - 256-entry sine table, result -127..127 / 0..255.
[x] ATAN2 ( dx dy -- angle ) - 0-255, 0 = east, 64 = down.
[x] LERP ( a b t -- n ) - t = 0-255.
[x] RING RING> >RING RING# - power-of-2 ring buffers. The head, tail and
    data sit at +4, +8 and +12: three CELLS, and a cell is four bytes here.
    They were 2/4/6 until testadv was first run.
[x] ZX0-DECOMPRESS - ZX0 v2 (what `zx0` / `salvador` emit), in Forth.
MEM-DECOMPRESS is gone rather than unticked: it was `bcall $feed`, the
    KERNAL's LZSA2 depacker in banked ROM. There is no banked ROM on a
    flat 65816 and no LZSA2 in the kernel, so the word could only ever
    have jumped into nothing. Compress with ZX0.

Graphics (NEEDS ADVGFX, after GRAPHIC) - tested by testadvgfx.
[x] CLIP-RECT CLIP-LINE CLINE - Cohen-Sutherland line clipping.
[x] FLOOD ( x y color -- ) - scanline flood fill, 128-span seed stack.
[x] FX-COPY ( sbank saddr dbank daddr u -- ) - cached 4-byte copies.
[x] AFFINE-ON AFFINE-RAY AFFINE-SPAN AFFINE-LINE AFFINE-OFF - rotozoom /
    mode-7 sampling (see VERAFX).
[-] circle / disc - GRAPHIC's OVAL/OVALF cover these (unclipped).
[-] text onto the bitmap - GRAPHIC's GTEXT draws it.

Audio (NEEDS ADVSND) - envelopes and ADPCM are tested by testadvsnd.
[ ] ENV-START ENV-RELEASE ENV-STOP ENV-TICK - per-frame ASR envelopes on
    all 16 PSG voices; arm with ' ENV-TICK IRQ.
[ ] PCM-PLAY ( addr ud rate -- ) PCM-STOP PCM-PLAYING? PCM-LOOP -
    background FIFO streaming off the AFLOW interrupt, auto-disarm,
    looping. The X16 took a bank and an offset; a flat 24-bit address
    says the same thing here. Blocked on AFLOW, above.
[ ] ADPCM-INIT ADPCM! ADPCM>PCM ( src dst u -- dst' ) - IMA ADPCM, low
    nibble first, 8-bit signed out. Offline only: decode whole buffers up
    front, then PCM-PLAY the result (Forth is too slow to feed the DAC
    live).

Storage / util
[-] DOS words - in the core (see DICTIONARY: DOS).
[x] BMX-LOAD ( c-addr u vbank vaddr -- ior ) - load a BMX v1 image: the
      palette into VERA's, the pixels into VRAM, rows BMX-STRIDE apart.
      No device number - there is no IEC bus. ior 1 = i/o (including a
      file shorter than its header claims), 2 = not a BMX v1 or a
      palette that would not fit, 3 = compressed (unsupported).
[x] BMX-SAVE ( c-addr u vbank vaddr -- ior ) - write one from VRAM,
      described by the variables below.
[x] BMX-WIDTH BMX-HEIGHT BMX-BPP BMX-PALSTART BMX-PALCOUNT BMX-BORDER
      BMX-STRIDE - set before BMX-SAVE; published by BMX-LOAD, which
      leaves them ALONE when it refuses a file.
[x] BMX-PAL ( -- addr ) - a VALUE: PALCOUNT*2 bytes of your own memory
      holding the palette, or 0 to use VERA's. USE IT. VERA's palette
      does not read back on this machine - entries you wrote come back
      exactly, entries nobody wrote come back as something that is not
      the palette in use - so BMX-SAVE from VERA writes bytes that are
      not colours, and the BMX-LOAD of that file installs them for real
      and the screen goes to pieces. With BMX-PAL set, BMX-SAVE writes
      that buffer and BMX-LOAD fills it.
[ ] TSCrunch decompression - not ported.
