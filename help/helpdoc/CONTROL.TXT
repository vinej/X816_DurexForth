=== CONTROL - X16 system control ===

[-] EDIT ( c-addr u -- ) - open the named file in the built-in X16 text editor
  (x16edit, ROM bank $0D; u=0 opens a new empty buffer). Edit, save (Ctrl-S),
  quit (Ctrl-Q), then INCLUDE the file to compile it. Typical loop:
    S" PROG.FS" EDIT   S" PROG.FS" INCLUDED
  EDIT saves/restores the data-stack zeropage the editor uses, resets the RAM
  bank to 0, closes the editor's files, and hides the mouse on exit; file I/O
  and console output after EDIT work normally.
SETBANK, B@ and B! are gone rather than unticked: they selected and
reached the X16's 8 KB RAM window at $A000, and a 65816 addressing
sixteen megabytes flat has no window to select. Ordinary @ and ! reach
any of it; HELP MEMORY has the map and the FAR-* allocator for SDRAM.
[x] SLEEP ( jiffies -- ) - wait jiffies 1/60-second ticks. 60 SLEEP waits ~1 s.
[x] MS ( u -- ) - wait u milliseconds on the free-running ms timer ($9F90,
    1 kHz wall clock at either CPU speed - exact at 8 and 14 MHz alike).
    1000 MS ~ 1 s.
[x] REBOOT ( -- ) - soft reboot through the reset vector.
[ ] KEYMAP ( c-addr u -- ) - set the keyboard layout by name (core; case does
    not matter; unknown names abort). S" DE-DE" KEYMAP ; the ROM layouts are
    ABC/X16 (default) EN-US/INT EN-GB EN-CA EN-US/DVO SV-SE DE-DE DE-CH DA-DK
    IT-IT PL-PL NB-NO HU-HU ES-ES FI-FI PT-BR PT-PT CS-CZ JA-JP FR-FR FR-BE
    IS-IS HR-HR SK-SK SL-SI ET-EE LV-LV LT-LT.

--- CPU speed (X816 SYSCTL $9F80 bit 2) ---
[x] TURBO?  ( -- flag )  true when the machine is EFFECTIVELY at 14 MHz. The
    MiSTer OSD's CPU Turbo option ORs over the software bit, so this reads
    the truth whichever side set it.
[x] TURBO   ( flag -- )  TRUE TURBO releases the domain's full 14 MHz; FALSE
    TURBO drops the software bit back to the exact 8 MHz average (the OSD
    may still hold the machine fast). Safe to flip at any time.
[x] CPU-MHZ ( -- u )     the effective CPU speed: 8 or 14.
[x] IOC! ( byte addr -- ) store a byte in bank $00 (the store half of IOC@;
    exists for the writable SYSCTL bits).

--- clock (battery RTC / jiffy timer) ---
[x] TICKS   ( -- ud )      the 24-bit jiffy counter (1/60 s) as an unsigned double.
[x] TIME@   ( -- h m s )   read the wall-clock time.
[x] DATE@   ( -- y mo d )  read the date (y = full 4-digit year).
[x] SETTIME ( y mo d h m s -- )  set the clock.  2025 7 8 14 30 0 SETTIME

--- I2C bus (SMC, RTC, and other I2C devices) ---
[x] I2CPEEK ( dev reg -- byte )   read a byte from I2C device dev, register reg.
    The SMC is device $42: $42 $22 I2CPEEK reads its mouse id.
[x] I2CPOKE ( dev reg val -- )    write val to I2C device dev, register reg.

--- break (X816 SMC NMI) ---
[x] Ctrl+Alt+PrtScr - the RUN/STOP-RESTORE of this machine: raises an NMI
    that aborts Forth code back to the interpreter with -28 (a CATCH in
    flight receives it). An NMI landing in Forth code (a runaway loop)
    aborts on the spot; one landing inside the kernel (an idle prompt,
    an SD transfer) is parked and delivered as the same -28 the next
    time KEY polls - so at the prompt it prints the abort and returns a
    fresh prompt. Not a word; it works BECAUSE the loop is stuck.

An uncaught -28 prints one of two words, and the difference is the
message, not the code - CATCH sees -28 either way:
    break   you pressed the key. The machine did as it was told.
    brk     a BRK instruction executed. NOBODY MEANT THAT. It is a bug
            in compiled code - a branch operand left as two $00 bytes
            reads as BRK, which is how the OF bug hid for a whole stage.
            If this appears without you touching the keyboard, the word
            you just ran is compiling something wrong.

--- power / debug ---
[-] MONITOR  ( -- )   enter the built-in machine-language monitor (exit with X;
                  it does NOT cleanly return - reset afterward).
[x] RESET    ( -- )   hardware reset via the System Management Controller -
             the same command Ctrl+Alt+Del raises.
[x] POWEROFF ( -- )   power the machine off via the SMC.
