=== LOGIC - Comparison and logic ===

Comparisons return TRUE (-1, all bits set) or FALSE (0).

[x] 0= ( x -- flag ) - equal to zero? (also logical NOT). 0 0=  ->  -1
[x] 0< ( n -- flag ) - negative? -3 0<  ->  -1
[x] 0> ( n -- flag ) - positive?
[x] 0<> ( x -- flag ) - non-zero?
[x] = ( a b -- flag ) - equal? 5 5 =  ->  -1
[x] <> ( a b -- flag ) - not equal?
[x] < ( n1 n2 -- flag ) - signed less-than. 3 9 <  ->  -1
[x] > ( n1 n2 -- flag ) - signed greater-than.
[x] U< ( u1 u2 -- flag ) - unsigned less-than.
[x] U> ( u1 u2 -- flag ) - unsigned greater-than.
[x] WITHIN ( n lo hi -- flag ) - is lo <= n < hi? 5 0 10 WITHIN  ->  -1

--- these are CELL-wide, and that is the whole answer on 16 bits ---
There is no 16-bit = or < here and there should not be. A comparison
cannot see how wide the data WAS - it sees a cell - so the question is
never "compare these as 16 bits", it is "what is in this cell". Two
things decide that, and both happen before the comparison:

  from memory   W@ zero-extends, SW@ sign-extends (HELP MEMORY)
  from anywhere W>N and C>N sign-extend a value already in a cell
                (HELP BIT)

Get that right and every word on this page is correct as it stands. Get
it wrong and no 16-bit comparison would have saved you: $FFFF read with
W@ is 65535, and 65535 < 0 is FALSE because 65535 really is positive.
The bug is at the fetch, which is where the fix belongs.

AND, OR, XOR and INVERT do not care at all - they work on the bits in
the cell, and INVERT of a 16-bit value simply has 32 bits set. Mask with
65535 if you are putting it back into a 16-bit field, or use W! , which
stores the low half and does the masking for you.

--- more ---
Each is the negation of one above, so they cost nothing and read better
than 0= after a comparison.
[x] 0<= ( n -- flag ) - zero or negative? -3 0<=  ->  -1 ;  0 0<=  ->  -1
[x] 0>= ( n -- flag ) - zero or positive?
[x] <= ( n1 n2 -- flag ) - signed less-than-or-equal. 9 9 <=  ->  -1
[x] >= ( n1 n2 -- flag ) - signed greater-than-or-equal.

[x] U<= ( u1 u2 -- flag ) - unsigned less-than or equal.
[x] U>= ( u1 u2 -- flag ) - unsigned greater-than or equal.
[x] U<> ( u1 u2 -- flag ) - unsigned not-equal.
[x] U=  ( u1 u2 -- flag ) - unsigned equal.
    U<> and U= are ALIASES of <> and = - equality does not care about
    signedness, since the bits either match or they do not. They exist
    because this page names them; there is no separate behaviour to learn.
