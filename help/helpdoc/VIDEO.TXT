=== VIDEO - X16 video, screen and cursor ===

VERA is the X16's video chip. VPOKE/VPEEK do single random accesses; for bulk
access set the address once with VADDR then stream with V!/V@.

[x] VPOKE ( bank addr value -- ) - write a byte to VRAM (BASIC VPOKE
    bank,addr,value). 0 $1000 65 VPOKE
[x] VPEEK ( bank addr -- value ) - read a byte from VRAM (BASIC VPEEK(bank,addr)).
[x] VADDR ( bank addr -- ) - point the VERA data port at VRAM (auto-increment 1).
    bank is the 17th address bit.
[x] V! ( byte -- ) - store a byte through the data port (address auto-increments).
[x] synonym VSTORE V!
[x] V@ ( -- byte ) - read a byte through the data port (address auto-increments).
[x] synonym VREAD V@
[x] V!W ( w -- ) - store a 16-bit word through the data port, low byte first.
[x] synonym VWSTORE V!
[ ] SCREEN ( mode -- ) - set the video mode. 0=80x60, 1=80x30, 2=40x60, 3=40x30,
    128=320x240x256. 0 SCREEN
[x] COLOR ( fg bg -- ) - set the text colours used FROM NOW ON. 1 6 COLOR
    is white on blue. Text already on screen keeps the attribute it was
    drawn with - this is a pen, not a repaint - but CLS fills with the
    current colour, so `2 4 COLOR CLS` gives a coloured screen.
    The attribute byte is foreground in the low nibble, background in the
    high one, and TATTR reads it back. Values are masked to 0-15.
    It is a KERNEL call, not a poke: the blinking cursor has to undraw
    with the same attribute, so the console owns it (X816_core
    doc/KERNEL.md CON_COLOR).
[x] BORDER ( color -- ) - set the display border color (0-15).
[x] CLS ( -- ) - clear the text screen.
[x] LOCATE ( row col -- ) - move the text cursor (BASIC LOCATE row,col).
[x] CURSOR ( -- row col ) - read the cursor position (inverse of LOCATE).
[x] POS ( -- col ) - current cursor column.
[x] SCROLLX ( n -- ) - set layer-1 horizontal hardware scroll (0-4095).
[x] SCROLLY ( n -- ) - set layer-1 vertical hardware scroll (0-4095).
[x] TILE ( x y code attr -- ) - set a tile cell (BASIC TILE x,y,code,attr).
[x] TDATA ( x y -- code ) - read a tile's code (BASIC TDATA(x,y)).
[x] TATTR ( x y -- attr ) - read a tile's attribute (BASIC TATTR(x,y)).
--- X816 ---
[x] IOC@ ( addr -- byte ) - fetch a byte from bank $00, where the I/O page
    lives. VERA register readbacks need this: a plain C@ reads the program
    bank. 7 BORDER $9F2C IOC@ -> 7

--- the console font (the X816's CHARSET) ---
The console is VERA layer 0 and its font is ordinary VRAM the kernel filled
at boot. There is no charset ROM here, so unlike the X16's CHARSET these
take an ADDRESS, not a ROM number - and anything you can write is a
charset. A font is 256 glyphs x 8 bytes = 2 KB and must start on a 2 KB
boundary (the tile-base register holds addr>>11). A glyph is 8 bytes, one
per scanline, top first, bit 7 leftmost. Codes are CP437 and the tile index
IS the character code - no $20 bias, so 65 is the "A" the machine prints.

[x] FONT ( -- vaddr ) - $4000, the kernel's CP437, live at boot. The
    tilemap sits below it at $00000-$03FFF (128x64 cells of two bytes).
[x] FONT2 ( -- vaddr ) - $4800, the next 2 KB slot up. Free VRAM, yours.
[x] CHARSET ( vaddr -- ) - point layer 0 at a font. FONT CHARSET restores.
[x] GLYPH-ADDR ( base n -- vaddr ) - where glyph n of that font lives.
[x] FONT-COPY ( src dst -- ) - duplicate 2 KB of tile data.
[x] GLYPH! ( c-addr base n -- ) - write 8 bytes from memory into glyph n.
[x] GLYPH@ ( base n c-addr -- ) - read glyph n back into 8 bytes of memory.

Redefining a character, the whole loop - copy first, because editing FONT
edits the font being drawn with and there is no way back short of a reboot:
    CREATE MYGLYPH 8 ALLOT
    FONT FONT2 FONT-COPY            \ work on a copy
    $FF MYGLYPH C!  $81 MYGLYPH 1+ C!    ( ...8 bytes... )
    MYGLYPH FONT2 200 GLYPH!        \ redefine character 200
    FONT2 CHARSET                   \ and show it
Nothing stops you pointing CHARSET at a font you never wrote; the screen
fills with whatever those 2 KB happened to contain, and FONT CHARSET
typed blind still puts it back.
